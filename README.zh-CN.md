# write-agents-md

[English](README.md) | [中文](README.zh-CN.md)

用于**创建或审查** AGENTS.md（以及 CLAUDE.md、GEMINI.md 等智能体指令文件）的 Agent 技能，覆盖 global（全局）、project（项目）、nested（子目录）三种作用域。

这是一个**引导式写作技能，而非自动生成器**：只读地收集证据，只问证据无法回答的问题，一切权限与删除决定都留给用户。

## 工作方式

**第 1 步 — 确定作用域。** 从请求和已有上下文判断：global（用户级偏好）、project（仓库根目录）或 nested（子目录/包）；新建还是审查；目标文件；以及用户希望文件使用的语言——它可以与对话语言不同。只有"未知且会改变产出或触及权限"的问题才会被提出，默认不做全量访谈。global 文件由用户本人的偏好构成，不靠扫描仓库取证；project 工作只读相关的 README、包清单、CI 与已有指令文件，证据足以支持当前决策即停止；默认不盘点所有尚未写入的实现细节。

**第 2 步 — 新建或审查。**

- *新建*：文件只由可证实的项目事实与用户明确表达的偏好构成。影响工作流的授权或完成条件缺口以"选项 + 提问"呈现，绝不静默定案。缺乏依据的模板栏目直接省略，不为填满模板额外调查。
- *审查*：每条既有指令给出 KEEP / DROP / REWRITE 判定与一行理由，按五个维度评估——来源（provenance）、边界强度、缺失的权限、缺失的完成条件、上下文经济性——随后给出完整替代草案。区分当前事实、用户意图和历史来源；代码能证明功能存在，不能自动证明其成熟度或定位。历史不明就明确写 unknown；含糊的边界交回用户确认。事实准确不等于值得常驻：说明它能防止什么错误或节省什么重复发现成本。

**第 3 步 — 应用与验证。** 尊重仅审查的要求；未获明确批准不写入，已获批准的修改不重复请示。交付提议前检查，实际写入后回读：最终文件无占位符或编造命令、本地链接有效、语言正确，意图/范围/权限符合已批准的决定。无法验证之处如实说明，并区分配置中的命令与实际测试过的命令。取证围绕实质决策设定边界；证据足够即停止，无法核实的主张如实报告而非猜测。

## 核心理念

1. **上下文是预算** — 已加载指令消耗上下文，加载行为因工具而异；保留价值足以抵偿成本的规则。
2. **证据优先于发明** — 命令与偏好必须来自仓库或用户，绝不来自模板槽位。
3. **权限属于用户** — 实质缺口变成提问而非默认值；检查副作用与作用域，不擅自废除有意设置的工具限制。
4. **完成有边界** — 区分继续、结束和请求人工审查；如实报告未解决的阻塞，不做无止境验证。在相关输入和环境未变时复用已有检查；仅因相关改动、失败或未解决疑点才重复或扩大验证。
5. **模板是可选骨架** — 各取所需；仅当内容确有价值时才拆分文件。

## 安装

将整个目录复制到你的智能体技能目录，例如：

- **Pi**：`~/.pi/agent/skills/write-agents-md/`
- **Claude Code**：`~/.claude/skills/write-agents-md/`

然后对智能体说"帮我写 AGENTS.md""审查我的 CLAUDE.md"等即可触发。

## 项目结构

```text
write-agents-md/
├── SKILL.md                        # 技能入口：作用域、新建/审查两条路径、验证
├── assets/templates/               # 可选输出骨架
│   ├── root-AGENTS.md              #   极简项目根文件模板
│   └── section.md                  #   领域规则分节模板
└── references/                     # 按需查阅的参考
    ├── PRINCIPLES.md               #   为什么指令文件要保持小
    ├── TOOL-CONVENTIONS.md         #   各平台加载行为（未核实的起点）
    └── EXAMPLES.md                 #   示例：全局审查、新建、精简
```
